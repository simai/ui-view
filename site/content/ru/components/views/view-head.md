# Шапка списка

:badge[sf-view]{variant=main scheme=on-surface size=1} :badge[head="list"]{variant=tonal scheme=on-surface size=1} :badge[Версия 1.28.1]{variant=tonal scheme=neutral size=1}

Шапка списка стоит над записями. В строке заголовка — название списка. Строка действий отвечает, **что делать**: значок представления, «Фильтр» с закладкой, поля фильтра, «Очистить», поиск, «Создать» и меню «⋯». Значок представления открывает зону под ней — **как смотреть**: открытое представление и его меню по уровням, способ показа («Таблица», «Доска», «Карточки», «Календарь») и «Настроить вид». Число записей — внизу, в подвале списка.

Шапку рисует [представление данных](../view/), если у него записан атрибут `head="list"`; без атрибута над таблицей остаётся её собственная панель. Шапка собрана из частей SIMAI Framework — кнопок, переключателя, поля поиска, всплывающих окон, — а всё, что человек в ней выбрал, становится запросом представления (`query`): приложение отвечает записями, как на поиск или сортировку.

## Пример

Список заказов с шапкой. Выберите значение в поле «Состояние» или
«Менеджер», найдите заказ по номеру или клиенту, переключите «Таблица»,
«Доска», «Карточки» и «Календарь» — строка под списком покажет, какой запрос
получило приложение. Способа показа, которого нет на странице, в
переключателе нет совсем.

:::example {id="components/view-head" label="Заказы с шапкой"}
:::

## Разметка

```html
<sf-view aria-label="Заказы" heading="Заказы" head="list" preferences-key="shop.orders">
  <sf-view-table slot="content" aria-label="Заказы"></sf-view-table>
  <sf-pagination slot="pagination" page-sizes="10,20,50,100"></sf-pagination>
</sf-view>
```

`heading` — название списка в шапке; без него берётся `aria-label`.

## Что в шапке

| Строка | Части | Когда видна часть |
|:---|:---|:---|
| Заголовок | название | всегда |
| Действия | значок представления (первым): подсказка «Представление: <имя>», точка при несохранённых изменениях, цвет при открытом не основном представлении, включён, пока зона открыта | есть сохранённые представления, способы показа или настройки вида |
| | «Фильтр» с закладкой сохранения | всегда |
| | поля фильтра, «Очистить» | приложение назвало поля в `describe().fields`; набор полей у каждого представления свой (`settings.filter_fields`), открытое представление ставит свои поля |
| | поиск | всегда, шириной до 20rem |
| | «Создать» | у порта есть возможность `create-record`; это единственная залитая кнопка шапки, остальные пункты — в её меню |
| | «⋯» (поля записи, права, экспорт) | только при правах из `describe().permissions` |
| Зона «Представление» | имя открытого представления и меню представлений по уровням: системные, для всех, мои | приложение отдаёт сохранённые представления |
| | способ показа: «Таблица», «Доска», «Карточки», «Календарь» | способов в `describe().layouts` больше одного |
| | «Настроить вид» | всегда |
| | «Изменено»: сохранить для всех, сохранить как новое, сбросить | открытое представление изменено; «для всех» — при праве `shared_settings` и не для системного |

Поиск и фильтры складываются (И), значения одного поля — ИЛИ. На
телефоне (уже 600 px) в строке действий — значок представления, «Фильтр»
значком, поиск, «+» и «⋯»; в зоне — имя представления, значок способа
показа и значок «Настроить вид»; поля фильтра встают одной строкой с
прокруткой, а каждое окно шапки открывается нижней панелью.

## Что отдаёт приложение

Шапка спрашивает приложение через порт представления. Метод `describe()`
отвечает, из чего собрать шапку:

```js
view.setHostPort({
  version: '1.15.0',
  capabilities: ['row-actions', 'saved-views', 'create-record'],
  describe: () => ({
    fields: [
      {key: 'status', label: 'Состояние', propertyType: 'choice', filter: {options: STATUS}},
      {key: 'deadline', label: 'Крайний срок', propertyType: 'date'},
      {key: 'budget', label: 'Бюджет', propertyType: 'money', currency: 'RUB',
       filter: {operators: ['eq', 'gt', 'gte', 'lt', 'lte', 'between']}},
    ],
    layouts: ['table', 'board'],
    permissions: {record_fields: true, rights: true, export: true, share_filters: true, shared_settings: true},
  }),
  raise,
});
```

- `fields` — поля фильтра: ключ, название, тип свойства и варианты;
  условия по типу (дата, число, деньги, выбор, человек) шапка берёт сама.
- `layouts` — способы показа, которые приложение разрешает. Шапка
  предлагает только те, что набор может нарисовать; если способ один,
  переключателя нет ([Способы показа](/ru/guide/concepts/layouts/)).
- `permissions` — что открыть в «⋯» и можно ли сохранять общие настройки.
- `record_fields` — показать в «⋯» пункт «Настройки полей записи». Он
  открывает первую запись списка в карточке сразу в режиме настройки:
  раскладка карточки одна для таблицы, доски и страницы записи (см.
  [Карточка записи](/ru/components/views/view-properties/)).

В данных ответа приложение отдаёт сохранённые фильтры `saved_filters`,
представления `saved_views` и настройки вида `view_config`.

## Представления по уровням

Сохранённое представление — фильтр, поля фильтра, сортировка, способ
показа и колонки под своим именем. У каждого в `saved_views` есть уровень
`level`, и меню представлений в зоне группирует их так же:

| Уровень | Кто видит | Что можно |
|:---|:---|:---|
| `system` — «Системные» | все | открыть; изменение сохраняется новым представлением, само системное не меняется |
| `shared` — «Для всех» | все | изменить и сохранить для всех — при праве `shared_settings` |
| `personal` — «Мои» | только этот человек | изменить и сохранить сразу |

```js
saved_views: [
  {key: 'all', label: 'Все заказы', level: 'system', default: true},
  {key: 'unpaid', label: 'Ждут оплаты', level: 'shared', query: {filters: {status: {operator: 'in', values: ['wait']}}}},
  {key: 'mine', label: 'Мои заказы', level: 'personal', settings: {layout: 'board', filter_fields: ['status']}},
]
```

Открытое представление ставит свои поля фильтра (`settings.filter_fields`)
и свой способ показа (`settings.layout`). Если человек его изменил, у
значка представления точка, а в зоне — «Изменено»: сохранить для всех,
сохранить как новое или сбросить.

## Личные настройки на сервере

Открыта зона или нет, размер страницы и представление, которое человек
открыл последним, запоминаются за ним. Без сервера — в браузере, под
`preferences-key`. Если приложение хранит их за человеком (порт
`simai.dataview-port` 1.16.0 и возможность `personal-preferences` — для
вошедшего человека), они переезжают с ним на любое устройство:

- первый ответ на `query.change` несёт личный слой
  `data.preferences: {revision, page_size, view_zone, view}`;
- представление берёт из него размер страницы и состояние зоны, а
  представление `view` открывает само, как если бы человек выбрал его в
  меню;
- когда человек меняет размер страницы, открывает или закрывает зону или
  открывает другое представление, приходит `preferences.save` только с
  изменённым полем и ревизией слоя. При конфликте ревизий представление
  повторяет то же изменение один раз против `current_revision` из ответа.

```js
if (intent === 'preferences.save') {
  const layer = await savePreferences(user, payload.preferences, payload.base_revision);
  if (layer.conflict) return {answer: 'conflict', current_revision: layer.revision};
  return {answer: 'applied', data: {preferences: layer}};
}
```

## Запрос шапки

Всё, что человек выбрал в шапке, становится запросом представления и
уходит приложению одним `query.change`:

```js
{
  filters_chosen: ['status', 'manager'],        // какие поля стоят в шапке
  filters: {status: {operator: 'in', values: ['paid', 'sent']}},
  saved_filter: 'default',
  search: 'Ромашка',
  view: {id: 'all', type: 'table'},
  page: 1,
  per_page: 20,                                 // без своего размера страницы — 20
}
```

Приложение возвращает то, что применило, в `echo` — шапка рисует фильтры и
поиск по нему, а не по тому, что отправила.

## Намерения

| Намерение | Когда |
|:---|:---|
| `query.change` | фильтр, поиск, представление, способ показа |
| `view.open {key}`, `view.save`, `view.save_shared`, `view.delete` | меню представлений и «Изменено» |
| `preferences.save {preferences, base_revision}` | размер страницы, зона, открытое представление — при `personal-preferences` |
| `filter.save`, `filter.update`, `filter.rename`, `filter.share`, `filter.default`, `filter.delete` | сохранённые фильтры: закладка «Фильтра» и его окно |
| `settings.save {layer, view, type, patch, base_revision}` | «Настроить вид»: личное сохраняется сразу, общее — только при `shared_settings` |
| `view.create_record {item}` | «Создать» и пункт его меню |

## События

- `sf-view-display-change` — человек выбрал другой способ показа;
  `detail: {kind, previous}`. Событие отменяемое. Если его не отменили,
  представление меняет способ сразу, без перезагрузки, и один раз
  спрашивает приложение запросом нового способа.
  Отмеченные записи и открытая рядом карточка остаются.
- `sf-view-settings-open` — человек попросил настройку, которую приложение
  держит на своих страницах: права (`rights`), экспорт (`export`) или новое
  поле записи (`record-field-add`); `detail: {id}`.

## Способ показа из кода

```js
view.canDrawLayout('board');          // true — у набора есть доска
view.switchLayout('calendar');        // {outcome: 'applied', layout: 'calendar'}
view.switchLayout('map');             // {outcome: 'refused', reason: 'layout-unavailable'}
```

Таблица, которую поставила сама страница (со своими полями фильтра и
пунктами «Создать»), на время другого способа убирается из слотов и
возвращается с «Таблицей». Представление, сохранённое доской,
открывается доской.
