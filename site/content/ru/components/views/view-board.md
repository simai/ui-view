# Доска

:badge[sf-view-board]{variant=main scheme=on-surface size=1} :badge[Версия 1.1.1]{variant=tonal scheme=neutral size=1} :badge[Предварительная версия]{variant=tonal scheme=warning size=1}

Доска раскладывает записи по колонкам: колонки — значения одного поля (состояние заказа, выбор, ответственный, да или нет), карточки — записи. Перенести карточку в другую колонку — значит изменить это поле; изменение сохраняет приложение. В шапке колонки — её название, число записей и суммы денег.

Обычно доску рисует [представление данных](../view/) с `layout="board"` или по выбору «Доска» в [шапке списка](../view-head/): оно просит у приложения окно колонок, передаёт ответ доске и отвечает на её события. Доску можно поставить и саму, без представления, и отвечать на её события страницей.

## Пример

Заказы разложены по колонкам состояния. Перенесите карточку мышью или
клавишами (Пробел — отметить, Enter — взять, стрелки — нести): в «Отправлен»
можно только из «Оплачен», доска скажет это сразу. Заказ №1003 приложение
не даст перенести — карточка вернётся на место с причиной. В «Оплачен»
мягкий предел — две карточки: шапка покажет превышение, перенос разрешён.
«Показать ещё» просит у приложения следующие карточки колонки.

## Как устроено

Доска не хранит данных и не ходит в сеть. Внутри
[представления данных](../view/) порядок такой:

1. Представление просит у приложения **окно колонок** — тот же
   `query.change`, что у таблицы, с полем `window`:
   `{lanes: "status", per_lane: 20, totals: ["count", {sum: "amount"}]}` —
   поле колонок, сколько карточек в колонке и какие итоги.
2. Приложение отвечает колонками **одним ответом**: первые карточки каждой
   колонки, число записей в ней и её итоги — суммы денег, которые названы в
   настройках доски (`totals`).
3. Перенос карточки, «Показать ещё», «+» в колонке и открытие записи —
   события доски; представление превращает их в намерения приложения.

### Ответ на окно колонок

```js
{
  answer: 'applied',
  sequence: payload.sequence,
  data: {
    columns: [/* поля записи, как у таблицы */],
    records: [],
    total: 40,
    lanes: [
      {value: 'new', total: 12, records: [/* первые 20 */], cursor: 'new:20',
       totals: {amount: {RUB: '418000.00'}}},
      {value: 'paid', total: 3, records: [/* … */], cursor: null,
       totals: {amount: {RUB: '214500.00'}}},
    ],
    view_config: {layouts: {board: {/* настройки доски, ниже */}}},
  },
}
```

`value` — значение поля колонки, `total` — число записей колонки под
фильтром, `cursor` — откуда продолжать «Показать ещё» (`null` — карточек
больше нет), `totals` — суммы колонки по полю и по валютам: в колонке с
рублями и долларами — две строки. Суммы считает приложение по своим
настройкам доски, даже если в `window.totals` их ещё нет — в первом
запросе представление настроек доски не знает.

### «Показать ещё»

Представление спрашивает следующую порцию одной колонки:
`query.change`, в окне которого добавлены `lane: 'new'` и
`cursor: 'new:20'`.
Ответ — та же колонка с новыми карточками и новым `cursor`; доска
добавляет их в конец колонки (`appendLane`).

## Настройки доски

Настройки приходят в ответе приложения, в `view_config.layouts.board`:

```json
{
  "lane_field": "status",
  "lanes": {"order": ["new", "wait", "paid", "sent", "cancel"], "hidden": [], "collapsed": ["cancel"]},
  "empty_lanes": "show",
  "card_fields": ["client", "manager", "amount"],
  "totals": ["count", {"sum": "amount"}],
  "limits": {"paid": 4},
  "order": "sort",
  "per_lane": 20
}
```

| Ключ | Что задаёт |
|:---|:---|
| `lane_field` | поле, значения которого — колонки; названия, порядок и цвета колонок берутся из вариантов поля |
| `lanes` | порядок колонок, скрытые (вернуть — в «Настроить вид») и свёрнутые (узкая полоса с названием и числом) |
| `empty_lanes` | показывать ли колонки без карточек |
| `card_fields` | до четырёх полей под названием карточки; их рисуют общие отрисовщики полей SIMAI Framework |
| `totals` | число записей и суммы денег в шапке колонки |
| `limits` | мягкий предел колонки: шапка показывает «5 / 4» выделенным, перенос разрешён |
| `order` | `sort` — порядок сортировки вида; `manual` — ручной порядок, только если у источника есть поле порядка и сортировка не выбрана |
| `per_lane` | сколько карточек колонки в первом окне |

Строк по второму полю (дорожек) у доски нет.

## Перенос карточки

Перенести карточку — изменить поле колонки. Правила переноса задаёт
`board.moves`; пока карточку несут, колонка, куда нельзя, бледнеет и
говорит причину, а в меню карточки «Переместить в» такая колонка
недоступна.

```js
board.moves = {sent: {from: ['paid'], reason: 'В «Отправлен» — только из «Оплачен»'}};
```

Внутри представления перенос приходит приложению намерением `record.set`
с полем колонки, новым значением и ревизией записи. Ответ:

- `{answer: 'applied', record}` — карточка остаётся в новой колонке;
- `{answer: 'refused', reason, message}` — карточка возвращается, причина
  показывается сообщением и читается экранным диктором, фокус остаётся на
  карточке.

Отказ бывает по правилу, по праву, из-за неизвестной колонки или устаревшей
ревизии — например, запись уже изменил другой человек. Доска, поставленная
без представления, отправляет событие `sf-view-board-move`, а страница
отвечает методом `settleMove(id, answer)`.

## Клавиши и телефон

- Доска — одна остановка Tab. Влево и вправо — между колонками; вверх,
  вниз, Home и End — внутри колонки.
- Пробел отмечает карточку, как строку таблицы; Enter берёт её, стрелки
  несут; Shift+F10 открывает меню карточки; Escape снимает отметку.
- Уже 600 px колонки идут по одной на экран под переключателем колонок с
  числами; смахивание ведёт к следующей колонке.

## Ответы Larena

Larena отвечает доске своим методом `listBoard()`:

- одним сгруппированным запросом — первые 20 карточек каждой колонки и
  число записей всех колонок; «Показать ещё» — отдельно по колонке;
- описание доски — порядок, скрытые и свёрнутые колонки, до четырёх полей
  карточки, мягкие пределы; ручной порядок — только с полем порядка;
- перенос — изменение поля колонки с допустимыми колонками и отказами с
  причиной: правило, право, неизвестная колонка, устаревшая ревизия.

На миллионе записей в MySQL первое окно доски Larena отдаёт за 435 мс
(медиана), «Показать ещё» — за 40 мс.

## Параметры

Справочник собран из манифеста компонента в сборке-кандидате набора (`simai/ui-view@42a536582aa1`) и обновляется вместе с выпуском. Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `search-placeholder` — `searchPlaceholder`.

| | |
|:---|:---|
| Тег | `<sf-view-board>` |
| Назначение | Доска набора представлений: колонки по одному полю, карточки с полями (до четырёх) на месте «Кратко», перенос — изменение этого поля, которое подтверждает приложение. sf-view с layout="board" рисует её по окну колонок. |
| Контракт | `smart.view-board`, версия `1.1.1` |
| Жизненный цикл | экспериментальный: API может меняться между выпусками |

### Атрибуты

- `template` — `string`, по умолчанию `default`. Имя варианта шаблона для внешних шаблонов SfBaseElement.
- `root-class` — `string`, по умолчанию пусто. Классы, которые добавляются корневому элементу, который рисует компонент.
- `root-style` — `string`, по умолчанию пусто. Встроенные стили корневого элемента, который рисует компонент, включая пользовательские свойства.
- `size` — `string`, по умолчанию `1/2`, значения: `1/2`, `1`. Ступень размера шапок колонок, карточек и их кнопок.
- `title-field` — `string`, по умолчанию `title`. Ключ записи, который читает название карточки (иначе title, name, id).
- `order-field` — `string`, по умолчанию пусто. Поле ручного порядка у источника (describe().order_field). Без него колонка идёт по сортировке вида (C304 (2)).
- `sort-active` — `boolean`, по умолчанию `false`. В виде выбрана сортировка: ручной порядок внутри колонки выключен (C304 (2)).
- `sums-pending` — `boolean`, по умолчанию `false`. Строка сумм в заголовке каждой колонки остаётся пустой, пока setLaneTotals не принесёт суммы: для страницы, которая считает их после карточек. sf-view его не задаёт: суммы приходят вместе с карточками (C304).
- `selectable` — `boolean`, по умолчанию `true`. У карточек есть флажок выбора; Пробел отмечает карточку.
- `creatable` — `boolean`, по умолчанию `false`. «+» в шапке колонки и «Новая запись» в её меню: событие create со значением колонки.
- `movable` — `boolean`, по умолчанию `true`. Перенос разрешён; false отказывает в каждом переносе словами «Нет права менять».
- `aria-label` — `string`, по умолчанию пусто.
- `lanes` — `array`, по умолчанию `[]`. Окно колонок, которым ответило приложение (C304): первые per_lane записей каждой колонки, число записей колонки под фильтром и её суммы (C294), cursor для «Показать ещё».
- `fields` — `array`, по умолчанию `[]`. Описания полей (колонки sf-view): варианты поля колонок дают порядок, названия и цвета колонок; поля карточки рисуют отрисовщики полей SIMAI Framework.
- `options` — `object`, по умолчанию `{}`. layouts.board из simai.view-config/1: lane_field, lanes {order, hidden, collapsed}, empty_lanes show|hide, card_fields (до четырёх), totals (count, {sum: key}), limits {колонка: n} (мягкий, C304 (3)), order sort|manual, per_lane (20), swimlane_field (зарезервировано, C304 (4)).
- `moves` — `object`, по умолчанию `{}`. Правила переноса от приложения: {<куда>: {from: [...], reason}}; колонка с отказом бледнеет и показывает причину, пока карточку несут, и недоступна в «Переместить в».
- `actions` — `array`, по умолчанию `[]`. Действия приложения над отмеченными, после «Переместить в…».
- `selected` — `array`, по умолчанию `[]`. Отмеченные id.

## События

События приходят на сам элемент и всплывают.

- `sf-view-board-move` — `detail`: `{ id, field: string, from: string, to: string, before, revision: string|null, how: string }`. Карточку перенесли (мышью, клавишами, из меню карточки, с панели отмеченных): перенос виден сразу и бледен, пока приложение не ответит settleMove. Отмена события отказывает сразу.
- `sf-view-board-open` — `detail`: `{ id }`. Название карточки или «Открыть» в её меню (слово open): приложение открывает карточку записи (sf-view-properties, C289).
- `sf-view-board-create` — `detail`: `{ field: string, value: string }`. «+» в колонке: приложение открывает новую запись со значением колонки.
- `sf-view-board-more` — `detail`: `{ lane: string, cursor: string|null, offset: number }`. «Показать ещё» в колонке: приложение отвечает appendLane следующими записями этой колонки.
- `sf-view-board-select` — `detail`: `{ ids: array }`. Отметка изменилась (слово select).
- `sf-view-board-save` — `detail`: `{ collapsed: array, hidden: array, order: array }`. Колонку свернули, развернули или скрыли: настройки доски, которые нужно сохранить в виде (layouts.board.lanes).
- `sf-view-board-apply` — `detail`: `{ action, ids: array, scope: string }`. Действие приложения, выбранное для отмеченных на панели действий.

## Методы

- `settleMove(args: object)` — возвращает `object`. Ответ приложения на перенос: {answer: applied, record?} оставляет карточку; refused или conflict ({reason, message}) возвращает её и говорит причину.
- `appendLane(args: object)` — возвращает `object`. Следующие записи одной колонки от приложения (ответ на more).
- `setLaneTotals(lanes: array)` — возвращает `object`. Итоги колонок, которыми приложение ответило после карточек ([{value, totals}], суммы по валютам); карточки и cursor не меняются.

## CSS-переменные

Задаются на элементе или на любом предке. Имена сохранили прежнее имя компонента.

| Переменная | Тип | Что задаёт |
|:---|:---|:---|
| `--sf-view-board-lane-width` | `length` | ширина колонки |
| `--sf-view-board-gap` | `length` | промежуток между колонками |
| `--sf-view-board-lane-background` | `color` | фон колонки |
| `--sf-view-board-lane-radius` | `length` | скругление колонки |
| `--sf-view-board-refused-opacity` | `number` | непрозрачность колонки, куда переносить нельзя |

## Доступность

- Роль: `region`.
- Доступное имя: даёт сам компонент.
- Клавиши: `Tab`, `ArrowLeft`, `ArrowRight`, `ArrowUp`, `ArrowDown`, `Home`, `End`, `Enter`, `Space`, `Escape`.
- Фокус: Область с именем из aria-label (иначе «Доска»); одна остановка Tab на доску, стрелки внутри (между колонками влево и вправо, по шапке колонки, карточкам и «Показать ещё» вверх и вниз); вежливая живая область сообщает каждый перенос и отказ; после ответа на перенос фокус остаётся на карточке.
