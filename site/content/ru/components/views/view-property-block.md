# Блок свойств sf-view-property-block

`sf-view-property-block` — несколько свойств записи **внутри потока**:
сообщения чата, ленты, комментариев — везде, где содержимое идёт одно за
другим. Блок делает одно из двух:

- **показывает** данные записи — ассистент нашёл заявку и показывает её поля
  под ответом;
- **просит заполнить** несколько полей и отправить их. После ответа блок
  остаётся в потоке записью того, что отправлено, только для чтения.

Компонент в состоянии предварительной версии: он есть в сборке набора, но
ещё не вошёл в выпуск.

## Пример

Первый блок показывает запись. Во втором нажмите «Отправить» с пустыми
полями — блок отметит обязательные; укажите город «Москва» — приложение
откажет с сообщением у поля; любой другой город — блок покажет отправленное.

## Чем отличается от карточки записи

| | `sf-view-properties` | `sf-view-property-block` |
|:---|:---|:---|
| Где стоит | страница, боковая панель, отдельная страница | внутри потока, во всю его ширину |
| Данные | читает и пишет через порт приложения | поля приходят настройкой, без порта и сети |
| Устройство | разделы, группы, настройка вида | список полей или несколько групп, группы можно сворачивать |
| Правка | по группам или всё сразу | весь блок — один ответ: «Отправить» и «Отмена» |
| После ответа | запись, снова доступная для правки | отправленное, только для чтения, со строкой «Отправлено» |

Поля описываются **так же**, как в карточке записи: `key`, `label`,
`propertyType`, `value`, `required`, `readonly`, `width` (`half` или
`full`), `hint`, `options`, `when`. Каждое значение рисует общий набор
рендереров полей SIMAI Framework — тот же, что в карточке и в таблице.

## Ответ и его разбор

Нажатие «Отправить» сначала проверяет то, что блок знает сам: обязательные
поля заполнены, в полях с маской нет недописанного. Потом блок переходит в
`pending` и отправляет событие `sf-view-property-block-answer` с
`{id, accepted: true, values}`: в `values` — все показанные поля, которые
человек может менять, то есть ответ целиком. «Отмена» отправляет
`{id, accepted: false}`.

Приложение отвечает методом `settle()` словами порта записи:

```js
block.addEventListener('sf-view-property-block-answer', async (event) => {
  const {accepted, values} = event.detail;
  if (!accepted) return block.settle({answer: 'applied'});        // отменено
  const result = await server.save(values);
  block.settle(result.ok
    ? {answer: 'applied'}                                          // отправлено
    : {answer: 'refused', errors: result.errors, message: result.message});
});
```

Отказ с `errors` возвращает блок в `open`: сообщение встаёт под своим полем,
введённое сохраняется, фокус переходит к полю. Отказ с `reason: 'closed'`
или `'expired'` закрывает блок как просроченный.

## Параметры

Справочник по манифесту появится на этой странице вместе с выпуском набора,
в который войдёт компонент. До выпуска — основные параметры:

| Атрибут | Значения | По умолчанию | Что делает |
|:---|:---|:---|:---|
| `mode` | `view`, `edit` | `view` | показать поля или попросить их заполнить |
| `heading` | текст | пусто | строка заголовка; она же доступное имя блока |
| `heading-level` | `2`–`6` | `3` | уровень заголовка там, где стоит блок |
| `fields` | список (JSON в разметке, свойство важнее) | `[]` | описания полей |
| `groups` | список | `[]` | группы полей `{key, label, collapsible, collapsed, fields}` |
| `state` | `open`, `pending`, `accepted`, `declined`, `expired` | `open` | где сейчас ответ |
| `expires-at` | дата ISO 8601 | — | до какого времени можно ответить |
| `block-id` | идентификатор | пусто | имя блока у приложения; приходит в каждом событии |
| `disabled` | логический | нет | всё видно, ничего нельзя нажать |
| `size` | `1`, `1/2` | `1/2` | размер текста и полей; `1/2` — для сообщения |
| `cancelable` | логический | да | показывать ли «Отмена» |
| `submit-text`, `cancel-text` | текст | «Отправить», «Отмена» | подписи ответов |

События: `sf-view-property-block-answer` (`{id, accepted, values}`,
отменяемое), `sf-view-property-block-expired` (`{id}`),
`sf-view-property-block-open` (`{id, field, value}` — нажата ссылка на
запись или человека). Методы: `confirm()`, `cancel()`, `answer({accepted})`,
`settle(result)`, `open()`; свойство `values` — то, что уйдёт при отправке.

CSS-переменные: `--sf-view-property-block-radius`, `-inset`, `-gap`,
`-background-color`, `-border-color`.

Доступность: блок — область, названная заголовком (без заголовка —
«Данные»). Строка состояния — вежливая живая область; когда ответы уходят,
фокус переходит на неё. Ошибки полей — `role="alert"`.
