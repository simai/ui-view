# Блок в потоке

:badge[sf-view-flow]{variant=main scheme=on-surface size=1} :badge[Версия 1.3.0]{variant=tonal scheme=neutral size=1} :badge[Предварительная версия]{variant=tonal scheme=warning size=1}

Блок в потоке — несколько свойств записи **внутри потока**: сообщения чата, ленты, комментариев — везде, где содержимое идёт одно за другим. Блок делает одно из двух:

- **показывает** данные записи — ассистент нашёл заявку и показывает её поля под ответом;
- **просит заполнить** несколько полей и отправить их. После ответа блок остаётся в потоке записью того, что отправлено, только для чтения.

## Пример

Первый блок показывает запись. Во втором нажмите «Отправить» с пустыми
полями — блок отметит обязательные; укажите город «Москва» — приложение
откажет с сообщением у поля; любой другой город — блок покажет отправленное.

## Чем отличается от карточки записи

| | `sf-view-properties` | `sf-view-flow` |
|:---|:---|:---|
| Где стоит | страница, боковая панель, отдельная страница | внутри потока, во всю его ширину |
| Данные | читает и пишет через порт приложения | поля приходят настройкой, без порта и сети |
| Устройство | разделы, группы, настройка вида | список полей или несколько групп, группы можно сворачивать |
| Правка | по группам или всё сразу | весь блок — один ответ: «Отправить» и «Отмена» |
| После ответа | запись, снова доступная для правки | отправленное, только для чтения, со строкой «Отправлено» |

Поля описываются **так же**, как в карточке записи: `key`, `label`,
`propertyType`, `value`, `required`, `readonly`, `width` (`half` или
`full`), `hint`, `options`, `when`. Каждое значение рисует общий набор
рендереров полей SIMAI Framework — тот же, что в карточке и в таблице.

## Ответ и его разбор

Нажатие «Отправить» сначала проверяет то, что блок знает сам: обязательные
поля заполнены, в полях с маской нет недописанного. Потом блок переходит в
`pending` и отправляет событие `sf-view-flow-answer` с
`{id, accepted: true, values}`: в `values` — все показанные поля, которые
человек может менять, то есть ответ целиком. «Отмена» отправляет
`{id, accepted: false}`.

Приложение отвечает методом `settle()` словами порта записи:

```js
block.addEventListener('sf-view-flow-answer', async (event) => {
  const {accepted, values} = event.detail;
  if (!accepted) return block.settle({answer: 'applied'});        // отменено
  const result = await server.save(values);
  block.settle(result.ok
    ? {answer: 'applied'}                                          // отправлено
    : {answer: 'refused', errors: result.errors, message: result.message});
});
```

Отказ с `errors` возвращает блок в `open`: сообщение встаёт под своим полем,
введённое сохраняется, фокус переходит к полю. Отказ с `reason: 'closed'`
или `'expired'` закрывает блок как просроченный.

Справочник собран из манифеста компонента в выпуске набора `view-974a2524bd40` (версия 1.17.0) и обновляется вместе с выпуском. Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `search-placeholder` — `searchPlaceholder`.

| | |
|:---|:---|
| Тег | `<sf-view-flow>` |
| Назначение | Несколько свойств блоком в потоке (сообщение чата, лента, любой поток): показывает поля записи или просит заполнить несколько и отправить их, а затем хранит ответ только для чтения. Поля — описания в форме `sf-view-properties`, рисуют их отрисовщики полей SIMAI Framework; нажатие — событие, хост отвечает через `settle`. |

### Атрибуты

- `template` — `string`, по умолчанию `default`. Имя варианта шаблона для внешних шаблонов SfBaseElement.
- `root-class` — `string`, по умолчанию пусто. Классы, которые добавляются корневому элементу, который рисует компонент.
- `root-style` — `string`, по умолчанию пусто. Встроенные стили корневого элемента, который рисует компонент, включая пользовательские свойства.
- `mode` — `string`, по умолчанию `view`, значения: `view`, `edit`. `view`: поля показаны только для чтения, без нижней строки. `edit`: поля — элементы ввода, а ответы — в нижней строке («Отправить», «Отмена»); после ответа поля снова показаны только для чтения.
- `heading` — `string`, по умолчанию пусто. Строка заголовка; она же доступное имя блока. Без неё блок называется «Properties».
- `heading-level` — `string`, по умолчанию `3`, значения: `2`, `3`, `4`, `5`, `6`. Уровень заголовка там, где стоит блок.
- `state` — `string`, по умолчанию `open`, значения: `open`, `pending`, `accepted`, `declined`, `expired`. Где ответ (режим `edit`). `open`: элементы ввода и ответы. `pending`: ответ в пути (ставится нажатием). `accepted`: значения отправлены, только для чтения. `declined`, `expired`: только итог.
- `expires-at` — `string`, по умолчанию пусто. ISO 8601. После этого времени открытый блок считается просроченным и один раз сообщает об этом событием `sf-view-flow-expired`.
- `block-id` — `string`, по умолчанию пусто. Имя блока у хоста; возвращается в каждом событии.
- `disabled` — `boolean`, по умолчанию `false`. Элементы ввода и ответы видны, но недоступны (ответ уже в пути в другом месте потока).
- `size` — `string`, по умолчанию `1/2`, значения: `1`, `1/2`. Размер блока: текст, подписи и элементы ввода. 1/2 — внутри сообщения.
- `cancelable` — `boolean`, по умолчанию `true`. Предлагать ли «Отмену» рядом с «Отправить».
- `submit-text` — `string`. Подпись кнопки отправки; пусто — «Отправить» на языке страницы.
- `cancel-text` — `string`. Подпись кнопки отмены; пусто — «Отмена» на языке страницы.
- `empty-text` — `string`. Как читается пустое значение.
- `required-text` — `string`. Текст под обязательным полем, оставленным пустым, когда нажали «Отправить».
- `invalid-text` — `string`. Строка состояния, когда отправку остановили поля.
- `fields` — `array`, по умолчанию `[]`. Описания полей в форме `sf-view-properties` (`key`, `label`, `propertyType`, `value`, `required`, `readonly`, `width`, `hint`, `options`, `when` …). В разметке — JSON; свойство, заданное из скрипта, важнее.
- `groups` — `array`, по умолчанию `[]`. Именованные группы описаний полей, каждую можно сделать сворачиваемой (`collapsible`, `collapsed`). Важнее `fields`, если заданы оба.

## События

События приходят на сам элемент и всплывают.

- `sf-view-flow-answer` — `detail`: `{ id, accepted: boolean, values?: object }`. Человек ответил (словарь answer): «Отправить» со значениями или «Отмена». Отмените событие, чтобы блок остался открытым.
- `sf-view-flow-expired` — `detail`: `{ id }`. Открытый блок прошёл `expires-at`; сообщается один раз на каждое время.
- `sf-view-flow-open` — `detail`: `{ id, field: string, value: object }`. Нажато значение-ссылка (запись, пользователь), словарь open: `{id, field, value}`. Переход — дело хоста.

## Методы

- `open()` — возвращает `object`. Задаёт вопрос снова (состояние `open`); по запросу сборки отвечает `{accepted, reason, value}`, когда человек ответит или выйдет время.
- `answer(args: object)` — возвращает `object`. Отвечает так, как ответил бы человек: `accepted` true отправляет (после собственной проверки полей блоком), false отменяет. Отклоняется, если поля неверны, блок закрыт, недоступен или событие отменено.
- `confirm()` — возвращает `object`. «Отправить»; `data-sf-action="<id>.confirm"`.
- `cancel()` — возвращает `object`. «Отмена»; `data-sf-action="<id>.cancel"`.
- `settle(args: object)` — возвращает `object`. Ответ хоста на ответ, словами порта записи: `{answer: applied, values?}` показывает отправленные значения только для чтения; `{answer: refused, errors?, message?}` снова открывает блок и ставит каждую ошибку под её поле; `reason` closed или expired закрывает его.

## CSS-переменные

Задаются на элементе или на любом предке. Имена сохранили прежнее имя компонента.

| Переменная | Тип | Что задаёт |
|:---|:---|:---|
| `--sf-view-flow-radius` | `length` | скругление блока |
| `--sf-view-flow-inset` | `length` | внутренний отступ блока |
| `--sf-view-flow-gap` | `length` | промежуток между частями блока |
| `--sf-view-flow-background-color` | `color` | фон блока |
| `--sf-view-flow-border-color` | `color` | цвет рамки блока |

## Доступность

- Роль: `region`.
- Доступное имя: даёт сам компонент.
- Клавиши: `Tab`, `Enter`, `Space`.
- Фокус: Раздел, названный своим заголовком (`role=heading` уровня `heading-level`). Строка состояния — вежливая живая область, которая есть до того, как заговорит; когда ответы уходят, фокус переходит к ней; когда отправку остановили или отклонили — к первому полю с ошибкой.
