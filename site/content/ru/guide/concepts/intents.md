# Запросы и ответы

`sf-view` и `sf-view-properties` не ходят в сеть сами. Когда человек что-то
делает, компонент передаёт приложению **намерение** — имя и данные запроса.
Приложение отвечает одним объектом, и компонент рисует ответ. Связь между
ними называется **портом**: это объект, который страница отдаёт компоненту
методом `setHostPort()`.

## Как это устроено

### Порт

```js
const view = document.querySelector('sf-view');
view.setHostPort({
  version: '1.12.0',
  capabilities: ['row-actions'],
  async raise(intent, payload) {
    const response = await fetch('/api/orders/intent', {
      method: 'POST',
      headers: {'Content-Type': 'application/json'},
      body: JSON.stringify({intent, payload}),
    });
    return response.json();
  },
});
```

- `version` — версия порта, которую понимает приложение. `sf-view` говорит
  на порту `simai.dataview-port` версий от 1.0.0 до 1.13.0,
  `sf-view-properties` — на порту `simai.property-view-port`.
- `capabilities` — что приложение умеет сверх обязательного: например
  `row-actions` (действия над строками) или `saved-views` (сохранённые
  виды). Компонент не предлагает человеку того, чего приложение не умеет.
- `raise(intent, payload)` — функция, которая получает намерение и
  возвращает ответ сразу или обещанием (Promise).

### Ответ

Ответ на любое намерение — один объект:

```json
{"answer": "applied", "data": {"records": [], "columns": [], "total": 0, "echo": {}}}
```

| `answer` | Что значит | Что делает компонент |
|:---|:---|:---|
| `applied` | выполнено | рисует `data` |
| `conflict` | запись изменилась, пока человек на неё смотрел | сохраняет ввод человека и перечитывает данные |
| `refused` | отказано: нет прав или запрос неверен | показывает причину; при отказе в доступе убирает строки |
| `unavailable` | сейчас нельзя: сервер недоступен или возможности нет | показывает состояние ошибки и предлагает повторить |

`reason` объясняет отказ кодом (`forbidden`, `stale-revision`,
`capability-not-provided` и другие), `message` — фразой для человека.
Фразу компонент показывает как есть, текстом, а не разметкой.

### Намерения представления данных

| Намерение | Когда отправляется | Что в ответе `applied` |
|:---|:---|:---|
| `query.change` | поиск, фильтр, сортировка, другая страница или размер страницы | `columns`, `records`, `total` (или `has_next`), `echo` |
| `record.open` | человек открыл запись | ничего; что открыть, решает приложение |
| `record.mutate` | действие над строкой из `actions` записи | можно вернуть только изменённые `records` — перерисуются ровно они |
| `bulk.apply_selected` | действие над отмеченными строками | ничего или изменённые записи; при устаревшей ревизии — `conflict` |
| `bulk.apply_under_filter` | действие над всеми записями под фильтром (возможность `bulk-under-filter`) | ничего; приложение получает подтверждённое число записей |
| `query.count` | человек попросил точное число записей (возможность `count-on-request`) | число записей |
| `settings.save_personal` | человек поменял колонки | новая ревизия слоя настроек |
| `view.open`, `view.save`, `view.delete` | сохранённые виды (возможность `saved-views`) | вид и его записи |
| `view.create_record` | кнопка «Создать» (возможность `create-record`) | ничего; форму открывает приложение |
| `tree.expand`, `node.targets`, `node.move` | дерево записей (возможности `tree`, `tree-move`) | один уровень дерева; места, куда можно перенести узел |
| `record.set` | человек поставил флажок прямо в ячейке (возможность `inline-edit`) | изменённая запись |
| `record.reorder` | человек перетащил строки (возможность `row-reorder`) | новые позиции или ничего |
| `list.open` | «Показать все» под коротким списком | ничего; полный список открывает приложение |

`query.change` несёт номер запроса `sequence`. Ответ называет тот же номер,
и компонент применяет только ответ на последний запрос: если человек
быстро набирает поиск, медленный ответ на старую строку не затрёт новый.

### Намерения карточки записи

| Намерение | Когда отправляется |
|:---|:---|
| `record.load` | карточка открылась или сменился `record-id` |
| `group.save` | человек нажал «Сохранить» в группе: изменённые поля и ревизия записи |
| `record.save`, `record.create` | сохранение всей записи сразу; создание новой |
| `group.load` | чтение по группам (возможность `group-load`) |
| `field.options`, `field.upload` | варианты для поля-ссылки; загрузка файла |
| `record.open`, `record.delete` | переход по ссылке на другую запись; удаление |
| `view.save`, `view.reset`, `view.profile`, `view.create`, `view.rename`, `view.delete` | раскладка карточки и её именованные виды (возможность `view-settings`) |

## Почему так

Сетевые запросы, права и проверки у каждого сайта свои: REST, GraphQL,
формы Битрикса, очередь задач. Если бы компонент сам ходил в сеть, его
пришлось бы подстраивать под каждый сервер. Намерения делают границу
простой: компонент знает, *что* нужно человеку, приложение знает, *как* это
сделать и можно ли.

## Ограничения

- Ответ всегда один из четырёх: `applied`, `conflict`, `refused`,
  `unavailable`. Другое значение — ошибка программы, компонент её не
  рисует.
- Ревизия обязательна у каждой записи, если приложение принимает изменения:
  без неё нельзя отличить свежую запись от устаревшей.
