# Настройки

**Настройки** — то, что страница пишет в разметке: как выглядит компонент,
какие части у него есть, под каким ключом он помнит выбор человека. Данные
и права в настройки не входят: их отдаёт приложение через порт.

## Как это устроено

### Атрибуты

Большинство настроек — обычные атрибуты элемента:

```html
<sf-view-table
  aria-label="Задачи"
  layout="auto"
  list-fields="2"
  size="1/2"
  search-placeholder="Найти задачу">
</sf-view-table>
```

| Атрибут | Компонент | Что задаёт |
|:---|:---|:---|
| `aria-label` | все | доступное имя; обязательно |
| `layout` | `sf-view-table` | `table`, `list` или `auto` — таблица, пока контейнер не уже `list-below` (600 px), ниже — компактный список |
| `list-fields` | `sf-view-table` | сколько полей под заголовком показывает строка списка; поля выбираются по `priority` колонок |
| `size` | `sf-view`, `sf-view-table` | ступень размера: `1` или плотная `1/2` для административных экранов |
| `chrome` | `sf-view` | какие части рисовать: `toolbar pagination select settings`; пустое значение — ни одной, для списка внутри карточки |
| `row-cap` | `sf-view` | сколько строк показать во вложенном списке, с «Показать все» под ним |
| `preferences-key` | `sf-view`, `sf-view-table` | ключ, под которым запоминается выбор человека (см. [Запомненные предпочтения](../preferences/)) |
| `current` | `sf-view`, `sf-view-table` | `id` открытой записи: её строка отмечается `aria-current` |
| `record-id` | `sf-view-properties` | какую запись показать; смена значения загружает другую |

Каждому атрибуту соответствует свойство элемента с тем же именем в
camelCase: `list-fields` — `listFields`. Полный список атрибутов — в
справочнике каждого [компонента](/ru/components/).

### Слоты

`sf-view` собирает экран из частей. Части ставятся в слоты:

```html
<sf-view aria-label="Заказы">
  <sf-view-table slot="content" aria-label="Заказы"></sf-view-table>
  <sf-pagination slot="pagination" page-sizes="10,25,50"></sf-pagination>
</sf-view>
```

Слоты `toolbar`, `content` и `pagination` необязательны: у каждого есть
встроенный вариант. Атрибуты таблицы и строки страниц, поставленных в
слоты, работают как обычно.

### Настройки первой отрисовки

Если сервер уже знает первую страницу, он печатает её вместе с разметкой в
блоке `data-sf-settings` — в той же форме, что ответ на `query.change`.
Представление рисует её сразу, без заготовки, а порт потом отвечает на тот
же запрос в фоне:

```html
<sf-view aria-label="Каталог">
  <script type="application/json" data-sf-settings>
    {"first-answer": {"records": [{"id": "1", "revision": "r1", "title": "Первая"}],
      "total": 2400, "echo": {"page": 1, "per_page": 20},
      "columns": [{"key": "title", "label": "Название"}]}}
  </script>
  <sf-view-table slot="content" aria-label="Каталог"></sf-view-table>
  <sf-pagination slot="pagination" page-size="20"></sf-pagination>
</sf-view>
```

Пока ответа нет, представление показывает заготовку той же формы, что
список с данными. Число её колонок задаёт `expected-columns` (по умолчанию
4), число строк — размер страницы. Когда данные приходят, ничего не
сдвигается.

## Почему так

Настройки — это решение страницы о виде, и оно одинаково для всех людей.
Поэтому оно живёт в разметке, которую видно в исходном коде и которую
сервер может напечатать заранее. То, что выбирает каждый человек сам,
хранится отдельно — в предпочтениях.

## Ограничения

- Атрибут меняет вид, но не данные: колонки и записи приходят из ответа
  приложения или из методов `setColumns()` и `setRows()`.
- `expected-columns` — форма заготовки, а не ограничение: колонки приносит
  ответ.
