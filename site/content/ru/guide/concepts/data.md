# Данные

Компоненты набора показывают данные приложения и ничего не придумывают
сами. Таблице нужны две вещи: **колонки** — что показывать — и **записи** —
сами значения. Карточке записи нужна одна запись с полями, разложенными по
разделам и группам.

## Как это устроено

### Колонки

Колонка называет ключ значения в записи, подпись и тип значений:

```js
{key: 'status', label: 'Состояние', property_type: 'choice', options: [
  {value: 'active', label: 'Действует', scheme: 'success'},
  {value: 'draft', label: 'Черновик', scheme: 'neutral'},
]}
```

| Поле | Что задаёт |
|:---|:---|
| `key` | ключ значения в записи; обязательное поле |
| `label` | заголовок колонки |
| `property_type` | тип значений: `string`, `text`, `integer`, `number`, `date`, `datetime`, `boolean`, `choice`, `choices`, `user`, `record`, `relation`, `file`, `color`, `include` |
| `options` | подписи и цвета для `choice` и `choices`: `value`, `label`, `scheme`, `icon` |
| `role` | `title` — главная колонка записи; по ней называют строку, и она закреплена при прокрутке вбок |
| `sortable` | заголовок становится кнопкой сортировки |
| `priority` | чем меньше число, тем дольше колонка остаётся видимой, когда места мало; в компактном списке — какие поля показать |
| `visible`, `order`, `width`, `min_width`, `sticky` | раскладка по умолчанию; человек меняет её в настройках колонок |
| `variant` | вид значения внутри типа: `image` у файла, `scale` у числа, `badges` у `choices` |

Без `property_type` таблица печатает значение как есть: логическое значение
читается как «true», выбор — своим кодом. С типом значение рисует общий
набор отрисовщиков SIMAI Framework: выбор — цветной меткой, ссылку на
запись — ссылкой, файл — значком файла.

> В ответе приложения для `sf-view` поля колонки пишутся через
> подчёркивание (`property_type`, `min_width`) — так их описывает порт.
> Примеры на этом сайте, где таблицу наполняют напрямую методом
> `setColumns()`, передают тип как `propertyType`.

### Записи

Запись — объект со значениями под ключами колонок и тремя служебными
полями:

| Поле | Что это |
|:---|:---|
| `id` | постоянный идентификатор записи — строка или число |
| `revision` | ревизия записи: меняется при каждом изменении; с ней приложение отличает свежую запись от устаревшей |
| `actions` | действия, которые этому человеку можно выполнить над этой записью, например `["view", "ship"]` |

Компонент предлагает над записью только действия из её `actions`. Кнопку,
которой нет в списке, человек не увидит, — но проверку прав всё равно
делает сервер: видимость кнопки не разрешение.

### Значения сложных типов

Значение ссылки на запись или файла — объект:

```js
client: {value: 'k-12', label: 'ООО «Северный ветер»', href: '/clients/k-12'}
file: {value: 'f-1', label: 'Д-1041.pdf', mime: 'application/pdf', href: '/files/f-1'}
```

Подпись приезжает вместе со значением, поэтому ячейке не нужен второй
запрос, чтобы показать «ООО «Северный ветер»».

### Формат дат и чисел

Как показать дату или сумму, набор за приложение не решает: «2026-11-05»
остаётся «2026-11-05», пока приложение не скажет иначе. Порт `sf-view`
может нести функцию `formatFieldValue(field, value)`: она возвращает
строку для ячейки или `undefined`, если значение показать как есть.

```js
const dateFormat = new Intl.DateTimeFormat('ru-RU', {dateStyle: 'medium'});
view.setHostPort({
  version: '1.12.0',
  capabilities: [],
  raise,
  formatFieldValue(field, value) {
    if (field?.property_type === 'date' && value) return dateFormat.format(new Date(value));
    return undefined;
  },
});
```

Сервер может прислать и уже оформленную строку, но тогда сортировку по
этой колонке он делает по исходному значению.

## Почему так

Данные и права живут на сервере, и только сервер знает, что человеку
можно увидеть и сделать. Поэтому записи приходят уже отфильтрованными, с
ревизией и списком действий, а компонент ничего не решает за приложение.
Тип колонки задаёт приложение, потому что угадывать его по значению
ненадёжно: строка «2026-11-05» может быть и датой, и артикулом.

## Ограничения

- Колонка с `role: "title"` может быть одна; вторую компонент не закрепит.
- Значения, которых нет среди колонок, в таблице не показываются, но
  остаются в записи: их можно использовать в карточке или в своём коде.
