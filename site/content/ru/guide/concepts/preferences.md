# Запомненные предпочтения

Человек может переставить колонки, скрыть лишние, поменять ширину,
выбрать сортировку и размер страницы. Компоненты набора запоминают этот
выбор, и при следующем заходе таблица открывается такой, какой человек её
оставил.

## Как это устроено

Выбор хранится в общем хранилище SIMAI Framework `SF.Preferences` под
ключом `sf-table/<ключ>`. Ключ задаёт атрибут `preferences-key`:

```html
<sf-view aria-label="Заказы" preferences-key="shop.orders">
  <sf-view-table slot="content" aria-label="Заказы"></sf-view-table>
  <sf-pagination slot="pagination"></sf-pagination>
</sf-view>
```

Без ключа ничего не запоминается. Ключ — постоянное имя того, что
показывается (коллекция, список), а не адрес страницы: две страницы с
одним списком могут делить выбор человека.

| Поле | Кто пишет | Что в нём |
|:---|:---|:---|
| `columnSettings` | `sf-view-table` | раскладка колонок: `visible`, `width`, `order`, `pinned` (`start` или `end`) |
| `widths` | `sf-view-table` | ширины, которые человек задал перетаскиванием |
| `view` | `sf-view-table` | плотность (`compact`, `normal`, `spacious`), полосы, линии, одна строка в ячейке, закреплённая шапка |
| `sort` | `sf-view` | сортировка `[{key, direction}]` — первый запрос уже приходит в этом порядке |
| `pageSize` | `sf-view` | размер страницы — первый запрос уже просит его |

Вид под общим ключом `sf-table/*` — вид всех таблиц человека; вид под
ключом таблицы важнее него.

### В браузере и на сервере

Без сервера выбор хранится в браузере (`localStorage`, ключ
`sf-pref:<ключ>`). На сайте с личными кабинетами подключите хранилище
сервера — тогда выбор переезжает с человеком на любое устройство:

```js
SF.Preferences.useHost({
  save: (key, value) => fetch(`/preferences/${encodeURIComponent(key)}`, {
    method: 'PUT', headers: {'Content-Type': 'application/json'}, body: JSON.stringify(value), keepalive: true,
  }),
  load: (keys) => fetch(`/preferences?keys=${keys.map(encodeURIComponent).join(',')}`).then((r) => r.json()),
});
```

Чтобы и первый кадр был в виде человека, сервер кладёт его значения прямо
в страницу:

```html
<script type="application/json" data-sf-preferences>
  {"sf-table/shop.orders": {"v": 1, "sort": [{"key": "created_at", "direction": "desc"}], "pageSize": 50}}
</script>
```

Подробно хранилище описано в документации SIMAI Framework, в главе
[Персональный вид](https://ui.simai.io/ru/guide/smart-components/view-preferences/).

### Настройки колонок у приложения

Приложение может хранить раскладку колонок и само — слоями: общий слой для
всех и личный слой человека, каждый со своей ревизией. Тогда изменение
колонок приходит приложению намерением `settings.save_personal`, а в ответе
на `query.change` приложение возвращает `column_settings` с ревизией слоя.

перезагрузите страницу — таблица откроется в том же виде.

## Почему так

Вид таблицы — личное дело человека, а не решение страницы. Поэтому он
хранится отдельно от настроек и от данных: сброс вида ничего не меняет в
записях, а одна и та же страница у двух сотрудников выглядит так, как
удобно каждому.

## Ограничения

- Копия в браузере принадлежит браузеру, а не человеку: на общем
  компьютере её видит каждый. На сайте с входом храните выбор на сервере.
- Фильтры со значениями — не вид. Сохранённый набор фильтров — это
  сохранённый вид (`saved-views`), он хранится у приложения.
