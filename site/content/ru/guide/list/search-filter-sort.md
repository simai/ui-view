# Поиск, фильтр и сортировка

Поиск, фильтр и сортировку выполняет приложение на сервере: только оно
видит все записи. Список собирает выбор человека — слова в поиске, значения
полей фильтра, колонку сортировки — в один запрос `query.change`, а
приложение отвечает записями.

## Пример

Найдите заказ по номеру или клиенту, выберите значение в поле «Состояние»
или «Менеджер», нажмите заголовок колонки «Сумма». Строка под примером
покажет запрос, который получило приложение, и сколько записей оно нашло.
На телефоне «Фильтр» становится значком, поля фильтра встают одной
строкой с прокруткой вбок, а окно поля открывается нижней панелью.

## Перед началом

- Список уже загружается с сервера ([Загрузка данных с
  сервера](/ru/recipes/load-from-server/)).
- У `sf-view` записан атрибут `head="list"` — шапка списка с полем поиска и
  полями фильтра ([Шапка списка](/ru/components/view-head/)).

## Шаги

1. Назовите поля фильтра в `describe().fields`: ключ, название, тип
   свойства и варианты. Условия по типу (дата, число, деньги, выбор,
   человек) шапка берёт сама:

   ```js
   describe: () => ({
     fields: [
       {key: 'status', label: 'Состояние', propertyType: 'choice', filter: {options: STATUS}},
       {key: 'manager', label: 'Менеджер', propertyType: 'user', filter: {options: MANAGERS}},
     ],
   }),
   ```

2. Отметьте колонки, по которым можно сортировать, полем `sortable: true` в
   ответе. Заголовок такой колонки становится кнопкой: первое нажатие —
   по возрастанию, второе — по убыванию, третье снимает сортировку.

3. Прочитайте запрос на сервере. Поиск приходит строкой, фильтр — условиями
   по полям, сортировка — списком:

   ```json
   {"search": "ромашка", "filters": {"status": {"operator": "in", "values": ["wait"]}}, "sort": [{"key": "amount", "direction": "desc"}], "page": 1, "per_page": 20}
   ```

   Ищите по полям, по которым человеку ожидаемо искать: номер, имя, город.
   Поиск и фильтр складываются (И), значения одного поля — ИЛИ. Сортируйте
   только по колонкам с `sortable: true` — остальные ключи отклоняйте.

4. Верните в `echo` то, что применили. Фильтр, который сервер не принял,
   перечислите в `filters_rejected`: так шапка рисует фильтр и поиск по
   тому, что на самом деле применено, и не считает список отфильтрованным
   зря.

5. Свой фильтр рядом со списком — кнопки, переключатель, поле — меняет
   запрос методом `changeQuery()`:

   ```js
   const view = document.querySelector('#orders');
   statusButtons.addEventListener('click', (event) => {
     const status = event.target.closest('[data-status]')?.dataset.status;
     if (status === undefined) return;
     view.changeQuery({filters: status ? {status: {operator: 'in', values: [status]}} : {}, page: 1});
   });
   ```

## Результат

Каждое изменение поиска, фильтра или сортировки приходит приложению одним
запросом `query.change`. Поиск отправляется после паузы в наборе, а не на
каждую букву. Сортировка запоминается, если у представления есть
`preferences-key`; поля фильтра и их значения можно сохранить в
[представление](../views/).
