# Массовые действия

**Массовое действие** — одно действие над несколькими записями сразу:
«Отметить оплаченными», «Напомнить клиенту», «Удалить». Человек отмечает
записи флажками, под списком встаёт полоса групповых действий SIMAI
Framework `sf-bulk-actions`, а приложение получает одно намерение со всеми
отмеченными записями и отвечает. Ответ полоса показывает сама.

## Пример

Отметьте два заказа флажками — под списком встанет полоса «Выбрано 2».
Нажмите «Отметить оплаченными»: полоса уйдёт, отметка снимется,
а строка под примером покажет запрос и ответ приложения. Теперь отметьте
оплаченный заказ и ещё один и нажмите «Напомнить клиенту»: приложение
откажет, полоса покажет «Готово 0 из 2 · 2 не удалось», «Подробнее» с
причиной по каждой записи и «Повторить для 2»; записи остаются
отмеченными. Отметьте флажком в шапке всю страницу — в полосе встанет
«Выбрать все 40»: действие пойдёт ко всем записям под фильтром. Крестик
или Escape снимают отметку.

## Как это устроено

### Выбор

Флажки есть, когда у списка есть групповые действия (`bulkActions` или
`actions` строки страниц): у таблицы — колонка флажков, у карточек и
календаря — флажок на записи. Флажок в шапке колонки отмечает все записи
страницы и снимает отметку с них.

Отметки сохраняются, когда человек листает страницы: действие получает
все отмеченные записи. У каждого способа показа — таблицы, канбана,
карточек, календаря — отметки свои: при переключении они не переносятся,
а когда человек возвращается к способу, его отметки на месте. Полоса
действий на экране одна, для открытого способа.

### Полоса действий

Пока отмечена хотя бы одна запись, под списком стоит полоса:

- **«Выбрано N»** — сколько записей отмечено;
- **кнопки действий** — до трёх кнопок со значками; остальные действия и
  удаление — в меню «⋯»;
- **«Выбрать все N»** — все записи под фильтром, а не только страница;
  кнопка встаёт, когда отмечена вся страница, если приложение объявило
  возможность `bulk-under-filter`;
- **×** — снять отметку; Escape в списке или в полосе делает то же.

На телефоне полоса в одну строку: кнопка-значок первого действия и «⋯»
(в нём остальные действия и «Выбрать все N»);
пока список длиннее экрана, полоса прилипает к низу окна.

Действия называет страница — свойством `bulkActions` со значками:

```js
const view = document.querySelector('#orders');
view.bulkActions = [
  {id: 'paid', label: 'Отметить оплаченными', icon: 'payments'},
  {id: 'remind', label: 'Напомнить клиенту', icon: 'mail'},
];
```

или атрибутом `actions` строки страниц, парами `код:подпись` через
вертикальную черту, — тогда кнопки без значков:

```html
<sf-pagination slot="pagination" page-sizes="10,20,50,100"
  actions="paid:Отметить оплаченными|remind:Напомнить клиенту"></sf-pagination>
```

Опасное действие (`delete`, `remove`, `destroy`, `trash`) стоит последним
в «⋯» и выделено цветом ошибки; вопрос перед ним задаёт приложение
(`confirm_required`).

### Что приходит приложению

| Человек делает | Приложение получает |
|:---|:---|
| нажал действие при отмеченных записях | `bulk.apply_selected` {`action_id`, `record_ids`, `revisions`} |
| «Выбрать все N», затем действие | `bulk.apply_under_filter` {`action_id`, `filters`, `confirmed_total`} |
| × или Escape | ничего: список снимает отметку сам |

```json
{"action_id": "paid", "record_ids": ["o2001", "o2004"], "revisions": {"o2001": "1", "o2004": "3"}}
```

Если число записей под фильтром известно только приблизительно («~N»),
список перед `bulk.apply_under_filter` сначала спрашивает точное число
(`query.count`).

### Ответ приложения

Пакет выполняется или отклоняется целиком. Ответ полоса показывает сама:

| Ответ | Что в полосе |
|:---|:---|
| `applied` | полоса уходит, отметка снята, диктор говорит «Выбор снят» |
| `refused`, `unavailable` | «Готово 0 из 2 · 2 не удалось», «Подробнее» — каждая запись с причиной (`message` приложения), «Повторить для 2»; записи остаются отмеченными |
| `conflict` | то же; у записей из `conflicts` причина — «Данные успели изменить…» |

```json
{"answer": "refused", "reason": "action-not-allowed", "message": "Среди отмеченных есть оплаченные заказы — напоминать не о чем."}
```

```json
{"answer": "conflict", "conflicts": [{"id": "o2004", "current_revision": "4"}]}
```

Отказ полоса не повторяет уведомлением в углу. Событие `sf-view-answer`
по-прежнему несёт каждый ответ. После `applied` список перечитывает страницу; если
приложение вернуло изменённые записи в `data.records`, перерисовываются
ровно они.

## Почему так

Одно намерение на пакет — одна проверка прав и ревизий на сервере и один
ответ: человек не ждёт по запросу на каждую запись, а приложение не
выполняет пакет наполовину. Ответ стоит там же, где кнопка, — человек
видит, что получилось, и может повторить, не отмечая записи заново.

## Ограничения

- Полоса `sf-bulk-actions` есть в SIMAI Framework, над которым собран этот
  сайт; на более старой паре без неё список рисует прежнюю строку: список
  действий, «Применить», «Для всех» и крестик.
- Отмеченная запись, которой уже нет в текущей выдаче, в пакет не
  попадает.
