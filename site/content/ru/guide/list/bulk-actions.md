# Массовые действия

**Массовое действие** — одно действие над несколькими записями сразу:
«Отметить оплаченными», «Напомнить клиенту», «Удалить». Человек отмечает
записи флажками, под списком появляется строка действий, а приложение
получает одно намерение со всеми отмеченными записями.

:::diagram {engine=mermaid title="От флажка до результата"}
sequenceDiagram
  participant P as Человек
  participant V as sf-view
  participant A as Приложение
  P->>V: отмечает записи, выбирает действие
  V->>A: bulk.apply_selected (код, id, ревизии)
  A-->>V: applied и строка результата
  V-->>P: список обновлён, результат на экране
:::

## Пример

Отметьте несколько заказов флажками — под списком встанет строка
«Отмечено: N». Выберите в ней «Отметить оплаченными» или «Напомнить
клиенту» и нажмите «Применить»: строка под примером покажет, что ответило
приложение, а список обновится. Крестик в конце строки снимает все
отметки без действия.

## Как это устроено

### Выбор

Колонка флажков есть у таблицы списка по умолчанию; флажок в шапке
колонки отмечает все записи страницы и снимает отметку с них.

### Строка действий

Пока отмечена хотя бы одна запись, под списком стоит строка действий:

- **«Отмечено: N»** — сколько записей отмечено;
- **«Выберите действие»** — список действий, которые назвала страница;
- **«Применить»** — выполнить выбранное действие над отмеченными;
- **×** («Снять выделение») — снять все отметки.

Действия перечисляет страница — в атрибуте `actions` строки страниц,
парами `код:подпись` через вертикальную черту:

```html
<sf-view aria-label="Заказы" head="list">
  <sf-view-table slot="content" aria-label="Заказы"></sf-view-table>
  <sf-pagination slot="pagination" page-sizes="10,20,50,100"
    actions="paid:Отметить оплаченными|remind:Напомнить клиенту"></sf-pagination>
</sf-view>
```

Сборка, которая ставит голое представление, отдаёт те же действия
свойством `view.bulkActions = [{id, label}]`.

### Что приходит приложению

Действие над отмеченными всегда приходит намерением `bulk.apply_selected`,
даже если отмечена одна запись:

```json
{"action_id": "paid", "record_ids": ["o2001", "o2004"], "revisions": {"o2001": "1", "o2004": "3"}}
```

Код действия не обязан быть в `actions` записи: право на пакет проверяет
приложение.

### Ответ приложения

Приложение проверяет права и ревизии. Если хотя бы одна запись изменилась,
пока человек на неё смотрел, оно отказывает всему пакету ответом
`conflict` со списком устаревших записей:

```json
{"answer": "conflict", "conflicts": [{"id": "o2004", "current_revision": "4"}]}
```

Иначе выполняет действие и отвечает `applied`; может вернуть `message` —
строку результата: «Отмечено оплаченными: 1 из 2 (остальные уже оплачены)».
Список перечитывает страницу; если приложение вернуло изменённые записи в
`data.records`, перерисовываются ровно они.

## Почему так

Одно намерение на пакет — одна проверка прав и ревизий на сервере и один
ответ: человек не ждёт по запросу на каждую запись, а приложение не
выполняет пакет наполовину.

## Ограничения

- Действие над всеми записями под фильтром, а не только отмеченными, —
  отдельное намерение `bulk.apply_under_filter`; приложение объявляет его
  возможностью `bulk-under-filter`.
- Отмеченная запись, которой уже нет в текущей выдаче, в пакет не
  попадает.
