# Связь с сервером

Компоненты набора говорят с сервером через порт: функция `raise` на
странице пересылает намерение на сервер и возвращает его ответ. Набору всё
равно, на чём написан сервер, — важна только форма запроса и ответа.

## Начните здесь

Проще всего завести на сервере один адрес на список, который принимает
`{intent, payload}` и отвечает объектом `{answer, data}`:

:::diagram {engine=mermaid title="Путь намерения"}
sequenceDiagram
  participant V as sf-view
  participant P as raise на странице
  participant S as Сервер
  V->>P: query.change, sequence 4
  P->>S: POST /api/orders/intent
  S-->>P: answer applied, data
  P-->>V: тот же ответ
:::

Что сервер делает всегда, на любой платформе:

- **проверяет права** на каждое намерение — видимость кнопки в браузере не
  разрешение;
- **принимает только известные поля** сортировки и фильтров;
- **сверяет ревизию** записи перед изменением и отвечает `conflict`, если
  она устарела;
- **возвращает `sequence`** запроса в ответе на `query.change`.

## Платформы

- [Обычный REST](rest/) — любой сервер, который отвечает JSON.
- [Laravel и Larena](laravel/) — контроллер Laravel; Larena.
- [1С-Битрикс](bitrix/) — контроллер модуля Битрикса.
