# Поиск, фильтры и сортировка

Поиск, фильтры и сортировку выполняет сервер: только он видит все записи.
Представление собирает выбор человека в один запрос `query.change`.

## Перед началом

- Список уже загружается с сервера ([Загрузка данных с сервера](../load-from-server/)).

## Шаги

1. Отметьте колонки, по которым можно сортировать, полем `sortable: true` в
   ответе. Заголовок такой колонки становится кнопкой: первое нажатие —
   по возрастанию, второе — по убыванию, третье снимает сортировку.

2. Прочитайте запрос на сервере. Поиск приходит строкой, сортировка —
   списком:

   ```json
   {"search": "казань", "filters": {"status": "new"}, "sort": [{"key": "created_at", "direction": "desc"}], "page": 1, "per_page": 25}
   ```

   Ищите по полям, по которым человеку ожидаемо искать: номер, имя, город.
   Сортируйте только по колонкам с `sortable: true` — остальные ключи
   отклоняйте.

3. Верните в `echo` то, что применили. Фильтр, который сервер не принял,
   перечислите в `filters_rejected`: так представление знает, какой
   запрос на самом деле применён, и не считает список отфильтрованным.

4. Свой фильтр рядом со списком — кнопки, переключатель, поле — меняет
   запрос методом `changeQuery()`:

   ```js
   const view = document.querySelector('#orders');
   statusButtons.addEventListener('click', (event) => {
     const status = event.target.closest('[data-status]')?.dataset.status;
     if (status === undefined) return;
     view.changeQuery({filters: status ? {status} : {}, page: 1});
   });
   ```

   Можно и проще: держать выбранный фильтр в своей переменной, учитывать
   его в `raise` и вызывать `view.refresh()` — так сделан фильтр по
   состоянию в примере «Заказы» на [главной странице](/ru/).

## Результат

Каждое изменение поиска, фильтра или сортировки приходит на сервер одним
запросом. Поиск отправляется после паузы в наборе, а не на каждую букву.
Выбор сортировки запоминается, если у представления есть
`preferences-key`.
