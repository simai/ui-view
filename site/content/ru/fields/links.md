# Люди и связи

Три типа ссылаются на других: пользователь `user`, запись `record` и связь
`relation`. Имена и названия приложение передаёт уже готовыми — набор не
превращает идентификатор в название.

:::example {id="fields/links" label="Люди и связи"}
:::

## Пользователь — `user`

| | |
|:---|:---|
| Значение | `{value, label, avatarText, href}`: идентификатор, имя, буквы для аватара, адрес профиля |
| В таблице и карточке | аватар с буквами и имя |
| В правке | выпадающий список сотрудников, который даёт приложение |
| Что уходит в сохранение | `{value, label}` выбранного или `null` |

## Запись — `record` и связь — `relation`

| | |
|:---|:---|
| Значение | `{value, label, href}`; `href` — только когда запись можно открыть |
| В таблице и карточке | название; с `href` — ссылка |
| В правке | выпадающий список записей, который даёт приложение |
| Что уходит в сохранение | `{value, label}` выбранной записи или `null` |

Нажатие на ссылку в карточке не переходит по адресу само: карточка
отправляет приложению запрос `record.open` с полем и значением, а куда
вести — решает приложение.

## Настройки

| Настройка | Что задаёт |
|:---|:---|
| `placeholder` | подсказка пустого поля |
| `searchPlaceholder` | подсказка поиска в списке |
| `required`, `readonly` | обязательное поле и поле только для чтения |

## Откуда берутся кандидаты

Список для выбора даёт приложение: карточка спрашивает его запросом
`field.options` — с полем, строкой поиска и курсором следующей страницы — и
ждёт ответ `{answer: "applied", options_page: {items, next_cursor, total}}`.
Для этого хост карточки объявляет возможность `field-options`. Без неё —
или если приложение ответило `refused` — поле остаётся таким, как в
просмотре: значение видно, выбрать другое нельзя.
