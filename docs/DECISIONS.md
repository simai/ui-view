# Decisions

The set's own questions, one `## D<n>` each: options, cost, recommendation and
outcome (set standard draft 1.1 §2.4). A decision that binds every set is an
owner row C## in ui-control `control/docs-review/decisions.md` (§2.5); the
ones this set follows are in the Answers table with their record.

## D1 — The site's languages before the English text

- Options: (a) English as the default URL now, its pages as drafts; (b) the
  registry's layout with `ru` and `en` declared, Russian at the root until
  English text is accepted; (c) Russian only.
- Cost: (a) Docara needs a published English home to make English the
  default (`LOCALE_DEFAULT_HOME_MISSING`): the root would lead to an empty
  `/en/`; (c) moves every address later.
- Recommendation: (b). Every address already carries its language;
  `docara locale add en --default` moves the root and the redirects when the
  first English text is accepted.
- Outcome: (b), view round 1 E10.

## D2 — The home hero's effect

- Options: an effect of the ui-effects catalogue, or none.
- Cost: an effect is a look question; none leaves the hero a plain band.
- Recommendation: `heat-mosaic` (a grid of cells a wave of shades passes over,
  the set's own among the sites; the owner may name another.
- Outcome: `heat-mosaic`, pinned with the catalogue commit in
  `site/docara.json`; shown for review on ui-view.test.

## D3 — The passport's `docs` URL while view.simai.io does not serve the site

- Options: (a) leave `https://view.simai.io/`; (b) empty, as §3.4 asks;
  (c) the GitHub repository.
- Cost: (a) a passport naming a site that answers with a self-signed
  certificate; (b) the component-set schema (ui-source
  `contracts/schema/component-set.v1.schema.json`) requires an https URL, so an
  empty value fails the passport test; (c) a URL that is not the docs.
- Recommendation: (b) once the schema allows it (Framework order through the
  dispatcher: `docs` may be empty); until then (a) stays.
- Outcome: waits the Framework order; round item E12 carried.

## D4 — The version the site reports during the round

- Options: the last release (1.8.1) or the round's target (1.9.0) as a
  candidate.
- Cost: 1.8.1 names a release that does not run over the pair the site is
  built on.
- Recommendation: 1.9.0 as «кандидат выпуска»; `site/scripts/build-pages.mjs`
  shows a version the release locks do not hold as this build's candidate.
- Outcome: `package/package.json` 1.9.0 in round view-r1.

## D5 — Which file is the journal's source

- Options: component.json `x-history`, or `units.json` as written.
- Cost: two sources drift.
- Recommendation: component.json `x-history` is the source (kind, consumer
  note, evidence per version); `package/docs/view/units.json` is generated by
  `package/scripts/write-units.mjs` and checked.
- Outcome: as recommended (dispatcher, standard draft 1.1 §15), under the key
  `x-history`: the component standard (gate 1 §4) refuses an unknown top-level
  field, and `history` is not one of its own. The same holds for
  `x-framework-first` (§7.3 names `framework_first`). The set standard 1.4.0
  should name the `x-` keys, or the component standard admit the two.
